# BirdBox

Автономный датчик звуков на ESP32 и сервер. Плата спит, просыпается, слушает 1 секунду; при громком
звуке пишет 4 секунды и отправляет на сервер. Сервер определяет тип звука (птица, автомобиль, самолёт,
вертолёт, поезд, человек, ветер и др.), вид птицы, считает показатели модуля «Оптика», ведёт журнал
событий и GPS-аномалий.

## 1. Структура

    server/      сервер: Flask, PostgreSQL, YAMNet, BirdNET
    firmware/    прошивка ESP32 / ESP32-S3 (PlatformIO)
    tools/       fake_device.py: имитация платы
    legacy/      исходники C#-приложения BirdTrack Pro (для работы не нужны)
    docker-compose.yml   PostgreSQL в Docker (необязательно)

## 2. Требования

- Python 3.11 (рекомендуется). Проверка: `python --version`. Для 3.12 и новее установка TensorFlow
  может завершиться ошибкой; в этом случае используйте 3.11.
- PostgreSQL 14+ или Docker.
- Около 5 ГБ на диске. Интернет при первой установке и первом запуске (скачиваются пакеты и модели).
- Для работы с платой: пакет esptool, USB-кабель с передачей данных.

## 3. Запуск сервера

### 3.1. База данных

Вариант A (Docker):

    docker compose up -d

Параметры по умолчанию: пользователь postgres, пароль postgres, порт 5432.

Вариант B (установленный PostgreSQL). Если пароль пользователя postgres отличается от `postgres`,
задайте его переменной окружения до запуска сервера, в том же терминале.

Windows (cmd):

    set BIRDBOX_DB_PASSWORD=пароль

Linux / macOS:

    export BIRDBOX_DB_PASSWORD=пароль

Доступные переменные: BIRDBOX_DB_HOST, BIRDBOX_DB_PORT, BIRDBOX_DB_NAME, BIRDBOX_DB_USER,
BIRDBOX_DB_PASSWORD, BIRDBOX_SECRET_KEY. База birdbox создаётся автоматически.

### 3.2. Окружение и запуск

Windows (cmd):

    cd server
    py -3.11 -m venv .venv
    .venv\Scripts\activate
    pip install -r requirements.txt
    python app.py

Linux / macOS:

    cd server
    python3 -m venv .venv
    source .venv/bin/activate
    pip install -r requirements.txt
    python app.py

Сервер слушает порт 5000: `http://localhost:5000`. Нормальный запуск заканчивается строкой
`Running on http://127.0.0.1:5000`. При первом запуске и первом событии скачиваются модели YAMNet и
BirdNET; первое событие обрабатывается дольше остальных.

Ошибка `pkg_resources` при установке: `pip install "setuptools<81"`, затем повторить установку.

Среда разработки: в PyCharm и VS Code выберите интерпретатор `server/.venv` и запускайте `app.py`.

## 4. Проверка сервера без платы

1. Откройте `http://localhost:5000`, зарегистрируйтесь, создайте устройство (поля по умолчанию).
2. На странице устройства скачайте zip прошивки, распакуйте. Нужен файл `cfg.bin`.
3. В папке с `cfg.bin` выполните (с активированным окружением, путь к tools поправить):

        python путь/до/tools/fake_device.py cfg.bin synth

4. Обновите страницу устройства. Событие появится сразу; тип звука и колонка «Оптика» заполняются
   через 10-60 секунд.
5. Проверка GPS-аномалий, две команды с паузой в несколько секунд:

        python путь/до/tools/fake_device.py cfg.bin gps 52.2 21.0
        python путь/до/tools/fake_device.py cfg.bin gps 53.5 21.0

   На странице устройства появляется аномалия «скачок координат».
6. `http://localhost:5000/optics/`: исходная страница работы про оптический микрофон.

## 5. Проверка прошивки на плате

### 5.1. Платы

Поддерживаются: ESP32 (DevKit V1, WROOM-32 и аналоги), ESP32-S3 (DevKitC-1 и аналоги).
Не поддерживаются: ESP8266, ESP32-C3/C6/S2, Arduino, Raspberry Pi. Wi-Fi только 2,4 ГГц.

### 5.2. Адрес сервера

Плата не может обращаться к `localhost`. В поле «Адрес сервера» при создании устройства укажите
адрес компьютера с сервером в локальной сети, например `http://192.168.0.10:5000`
(узнать: `ipconfig` на Windows, `ip addr` на Linux). Плата и компьютер должны быть в одной сети.

Порт на Windows (PowerShell от администратора):

    New-NetFirewallRule -DisplayName "BirdBox 5000" -Direction Inbound -Protocol TCP -LocalPort 5000 -Action Allow

Если плата в другой сети, нужен публичный адрес сервера (проброс порта, туннель или VPS).
Настройки устройства (адрес, Wi-Fi, пороги) записываются в прошивку при скачивании zip; после любого
изменения zip скачивается заново.

### 5.3. Подключение микрофона INMP441

    INMP441   ESP32    ESP32-S3
    VDD       3V3      3V3
    GND       GND      GND
    L/R       GND      GND
    SCK       GPIO26   GPIO4
    WS        GPIO25   GPIO5
    SD        GPIO33   GPIO6

GPS-модуль (необязательно): TX модуля к GPIO16 (ESP32); включается настройкой на сайте.

### 5.4. Плата без микрофона

Тестовый режим: порог громкости = 0. Плата отправляет запись при каждом пробуждении. Проверяется
цепочка прошивка - Wi-Fi - сервер - журнал; тип звука при этом не значим.

### 5.5. Прошивка платы

1. Скачать zip со страницы устройства, распаковать (bootloader.bin, partitions.bin, firmware.bin,
   cfg.bin, flash.bat, flash.sh).
2. `pip install esptool`
3. Подключить плату. Порт: Диспетчер устройств (COM5 и т. п.) или `/dev/ttyUSB0`. При отсутствии порта
   установить драйвер CP210x или CH340.
4. Windows: `flash.bat COM5`. Linux / macOS: `sh flash.sh /dev/ttyUSB0`.
   Эквивалентная команда напрямую (ESP32):

        python -m esptool --chip esp32 --port COM5 --baud 460800 write_flash 0x1000 bootloader.bin 0x8000 partitions.bin 0x10000 firmware.bin 0x3F0000 cfg.bin

   Для ESP32-S3: `--chip esp32s3` и адрес bootloader.bin `0x0`.
   Если прошивка не начинается, удерживать BOOT при запуске.
5. Монитор порта:

        python -m serial.tools.miniterm COM5 115200

   Ожидаемые строки: `low=... high=... trig=1`, `/api/upload -> 200`.
6. Событие появляется в журнале на сайте.
7. Применение изменённых настроек без полной прошивки (только cfg.bin):

        python -m esptool --chip esp32 --port COM5 write_flash 0x3F0000 cfg.bin

Если в zip нет файлов `.bin`, шаблон прошивки не собран (раздел 6).

### 5.6. Неисправности

    Сообщение в мониторе     Причина                          Действие
    cfg missing              cfg.bin не записан               записать cfg.bin (0x3F0000)
    wifi fail                неверный пароль или сеть 5 ГГц   пересоздать устройство, записать cfg.bin
    trig=0 постоянно         порог слишком высокий            порог 20 или 0
    -> -1 или не 200         неверный адрес / сервер выключен проверить адрес, порт, сервер
    нет вывода               кабель без данных / не тот порт  заменить кабель, проверить порт

### 5.7. Эмуляция

Эту прошивку полностью эмулировать затруднительно: нужны I2S-микрофон, Wi-Fi и раздел настроек cfg.
Сервер проверяется без платы через `tools/fake_device.py` (раздел 4). Эмулятор Wokwi принимает
объединённый образ (ESP32/ESP32-S3), но запуск этой прошивки в нём не проверялся:

    python -m esptool --chip esp32 merge_bin -o wokwi.bin --flash_mode dio --flash_size 4MB 0x1000 bootloader.bin 0x8000 partitions.bin 0x10000 firmware.bin 0x3F0000 cfg.bin

## 6. Сборка прошивки из исходников

Нужен PlatformIO (расширение для VS Code или CLI).

    pip install platformio
    cd firmware
    pio run
    python build_template.py

Если `pio` не найден: `python -m platformio run`. Файлы появляются в
`server/firmware_template/esp32` и `esp32s3`; сервер включает их в zip. Arduino IDE не поддерживается.

## 7. Данные и остановка

Записи звука: `server/data/audio` (не добавляются в git). Остановка сервера: Ctrl+C.
Остановка базы в Docker: `docker compose down` (данные сохраняются в томе).

## 8. Ограничения

- Исходный код прошивки на реальных платах не проверялся.
- Сервер и прошивка не проверялись автоматическими тестами; проверялся синтаксис Python.
- Регистрация открыта, HTTPS нет: для публичного доступа сервер не подготовлен.
- Тип звука определяется по записи 4 секунды; далёкий шум может быть классифицирован неверно.
- Модуль «Оптика» считает модель по записи; физического оптического микрофона в устройстве нет.
